# EduTest Web

Веб-версия учебной платформы: библиотека книг, читалка с оглавлением, ИИ-репетитор и тесты после изучения главы. Интерфейс на русском, адаптирован для компьютера и телефона.

## Возможности

- Учитель добавляет PDF (включая сканы страниц), EPUB, DOCX, TXT или Markdown; выбирает предмет и класс. PDF и EPUB обрабатываются в браузере постранично: существующий текст извлекается, изображения распознаются, результат можно проверить и исправить перед сохранением.
- Книга хранится на сервере, разбивается на главы и доступна всем вошедшим участникам этой платформы. Исходный файл можно скачать после входа.
- Ученик читает материал внутри платформы, меняет размер текста и отмечает изученные главы.
- ИИ объясняет выбранную главу, разбирает примеры, задаёт упражнения и обсуждает ответ ученика.
- После отметки «Глава изучена» создаётся проверенный тест по материалу. Один автоматический тест на главу переиспользуется; учитель может создать дополнительные тесты ИИ или вручную.
- Вопросы и варианты перемешиваются. Правильные ответы недоступны клиенту до окончания попытки. Время и подсчёт проверяются сервером, ответы сохраняются, перезагрузка не обнуляет таймер.
- Ученик видит историю и пояснения к ответам. Учитель видит результаты по своим книгам и встроенной общей учебной книге.
- Добавлен оригинальный короткий учебный материал по математике для 5 класса. Это материал EduTest, а не копия стороннего учебника.

## Локальный запуск

Требуется Node.js 24 LTS и npm.

```powershell
npm ci
Copy-Item .env.example .env.local
# Заполните .env.local серверными секретами.
npm run setup:local
npm run dev
```

Обязательные параметры: `GROQ_API_KEY`, `SESSION_SECRET` (случайная строка минимум 32 символа), `TEACHER_INVITE_CODE`, `APP_URL`. Модель по умолчанию — `openai/gpt-oss-120b`. Ключ Groq не совместим с прежним Mistral endpoint. Модель можно изменить через `GROQ_MODEL` на совместимую модель Groq со строгой JSON schema и reasoning_effort. В генерации применяется strict schema, после неё дополнительная Zod-проверка. Временная ошибка провайдера 5xx или `json_validate_failed` при создании теста повторяется один раз в пределах общего таймаута 55 секунд; ошибки квоты и авторизации не повторяются. Каждая попытка учитывается в общем бюджете запросов.

Локальные аккаунты создаются только явной командой `setup:local`. Их случайные пароли и приглашение сохраняются в игнорируемом `LOCAL_ACCESS.md`. В исходниках нет универсальных демо-паролей. Не выполняйте bootstrap для публичной базы.

Страница: `http://127.0.0.1:3000`. Для production-проверки:

```powershell
npm run build
npm run start
```

Данные локального режима находятся в `data/edutest.db`, файл не отслеживается Git. Предыдущий Flutter-проект расположен отдельно и не изменён; его личная база не импортируется автоматически.

## Подготовка к Vercel

1. Создайте приватный GitHub-репозиторий и отправьте рабочую ветку. Корень проекта — эта папка, не родительская папка с Flutter и аудитом.
2. Подключите репозиторий к Vercel как Next.js-проект.
3. Подключите постоянную Turso/libSQL базу и задайте `DATABASE_URL=libsql://...` и `DATABASE_AUTH_TOKEN`. Файловая SQLite на Vercel запрещена кодом: временный диск Functions не подходит для данных учеников и книг.
4. Добавьте Groq-ключ, новую `SESSION_SECRET`, новый `TEACHER_INVITE_CODE`, `GROQ_MODEL` и `APP_URL=https://ваш-домен`. Ни один секрет не должен иметь префикс `NEXT_PUBLIC_`.
5. Опубликуйте, создайте учительский аккаунт через приглашение и проверьте сохранение книги между запросами. Настройте резервные копии базы у провайдера.

Схема создаётся идемпотентно первым запросом. Все внешние сервисы используют HTTPS. Автогенерация запускается после изучения главы; cron не требуется.

Веб-приложение отправлено в GitHub xreder08/test-students, ветка feature/edutest-web. Vercel пока не опубликован: доступ к интеграциям команды возвращает 403. Для публикации нужен доступ и постоянная облачная база. Не передавайте токены в репозиторий или публичный чат.

## Безопасность и данные

- Пароли: scrypt с отдельной случайной солью. Сессии: случайные непрозрачные токены, в БД только HMAC; HttpOnly, SameSite и Secure для HTTPS production, срок 7 дней. При каждом запросе пользователь сверяется с БД.
- Учительский доступ выдаётся только по серверному приглашению. Права изменения книги проверяются на сервере; чужие попытки недоступны.
- Защита Origin для изменяющих запросов, параметры SQL, Zod-валидация входа и JSON от ИИ, транзакции создания/удаления книги и фиксации результата.
- Лимиты входа и операций хранятся в общей БД. На пользователя — 12 AI-запросов за 10 минут; общий защитный бюджет — 250 AI-запросов за 24 часа. Это ограничение приложения, дополнительно действуют лимиты Groq. Изменять бюджет следует в `src/lib/ai.ts`/`auth.ts` после оценки расходов.
- В Groq отправляется только выбранная глава и до 8 последних сообщений диалога. Пароли, база пользователей и API-ключ в браузер не отправляются. История чата не записывается в базу.
- Сторонние аналитические трекеры, удалённые шрифты и отправка учебной базы отсутствуют. Телеметрию Next можно отключить `NEXT_TELEMETRY_DISABLED=1`.
- Документы не исполняются как HTML; вывод текста и ИИ проходит через React. DOCX/EPUB распаковываются с ограничением итогового объёма; внешние ссылки/отношения не загружаются.
- `.env.local`, SQLite, данные входа, логи, трассы браузера и `.vercel` исключены из Git. Перед отправкой выполните `npm run check:secrets`.

Это одна учебная библиотека для участников одной платформы, а не многопользовательский SaaS с изолированными школами. Учителя и ученики этой установки видят общие книги; изменять/удалять их может владелец. Для нескольких школ необходима отдельная модель организаций.

## Ограничения

- Локально: до 100 МБ на файл, 10 миллионов символов, 2000 частей и 64 МБ распакованного текста DOCX/EPUB. На Vercel большие исходники требуют отдельной загрузки через файловое хранилище из-за ограничения тела запроса платформы.
- PDF-сканы распознаются встроенным OCR в браузере. Нечёткие изображения, сложные формулы и таблицы могут распознаваться с ошибками; перед сохранением учитель проверяет текст. DRM-защищённые EPUB не поддерживаются. Форматирование читаемой версии упрощается до текста; исходник сохраняется отдельно.
- Загрузка делит текст по заголовкам «Глава», «Урок», «Раздел», § и Markdown; очень длинные разделы дробятся по границам абзацев. Неоднозначное оглавление может потребовать подготовки файла учителем.
- ИИ может ошибаться в объяснениях и содержании тестов. Формат и допустимые ответы проверяются программно, учебные факты требуют проверки учителя.
- Проверка email, сброс пароля и админ-панель не реализованы. Регистрация ученика открыта, учителя — по приглашению.
- История результатов ограничена последними 100 попытками в обзоре. Среднее и число уникальных учеников считаются по показанной выборке.

## Проверки

```powershell
npm run typecheck
npm test
npm run build
npm audit
# Запущенный сервер на 127.0.0.1:3000, .env.local и установленный Chrome:
npm run test:e2e
npm run check:secrets
```

Unit-тесты проверяют пароли, плохой AI JSON, валидацию, разбиение глав, перемешивание/баллы, PDF/DOCX/EPUB и ограничения распаковки. Браузерный тест использует настоящий Groq и оригинальный синтетический учебный текст; проверяет приглашение, загрузку, репетитора, автотест, ручной тест, перезагрузку, deadline, доступ к попыткам и мобильный экран. Использует квоту Groq. Тест удаляет созданную книгу и тестовые аккаунты при успешном завершении.

Дополнительные проверки охватывают некорректный JSON, лимиты потока без Content-Length, ошибочные маршруты, конкурентную регистрацию, сохранение ответов и завершение попыток. Provider-тесты используют отдельную временную базу и имитируют ответы Groq; реальные AI-вызовы проверяются браузерными тестами. Результаты аудита 12 октября 2026 года — в [FULL_AUDIT_RU.md](FULL_AUDIT_RU.md).

Для повторной проверки уже загруженного большого учебника (ID можно взять из адреса страницы чтения):

```powershell
$env:EDUTEST_EPUB_EXISTING_BOOK='ID_КНИГИ'
$env:EDUTEST_EPUB_KEEP_BOOK='1'
npm run test:e2e
```

Для полного OCR-импорта вместо EXISTING_BOOK задайте `EDUTEST_EPUB_TEST_FILE` абсолютным путём к EPUB. `EDUTEST_EPUB_KEEP_BOOK=1` оставляет импортированную книгу в библиотеке; без этого импортный тест удаляет свою книгу после проверки. Полный OCR большого учебника занимает несколько минут.

Стек: Next.js App Router, React, TypeScript, libSQL/SQLite, Groq, Zod, pdf-parse, PDF.js, Tesseract.js, fflate, Playwright.

Для больших учебников локальная загрузка принимает файлы до 100 МБ, до 10 миллионов символов извлечённого текста и 2000 частей/глав. Длинные главы делятся на части до 12 тысяч символов: ИИ работает по выбранной части. Распакованный текст DOCX/EPUB ограничен 64 МБ; изображения внутри архивов не распаковываются. На Vercel для файлов больше лимита тела запроса платформы потребуется отдельная прямая загрузка в постоянное файловое хранилище; локальное увеличение лимита не снимает ограничение Vercel Functions.


## Распознавание сканированных учебников

При добавлении PDF или EPUB выберите язык (русский/английский или казахский/русский/английский), нажмите «Прочитать и распознать PDF» или «Прочитать и распознать EPUB», дождитесь обработки всех страниц, при необходимости исправьте текст и нажмите «Сохранить книгу». Не закрывайте вкладку во время обработки. Доступна отмена и повторный запуск. Если текстовый слой повреждён или неполон, включите распознавание всех страниц. Страницы PDF и EPUB становятся учебными разделами; длинные страницы делятся на части. ИИ использует этот текст для объяснений, упражнений и тестов. Самостоятельное понимание рисунков и безошибочное распознавание формул не гарантируется.

OCR выполняется локально в браузере в Web Worker. PDF.js worker, Tesseract WASM и языки rus/eng/kaz раздаются самим приложением из public/ocr. npm ci автоматически готовит их через postinstall; повторная подготовка — npm run setup:ocr. При первой установке требуется интернет для загрузки языковых моделей из официального tesseract-ocr/tessdata_fast (релиз 4.1.0). Пользовательские документы в этот источник не отправляются. public/ocr исключена из Git и восстанавливается установкой зависимостей. Оригинальный PDF или EPUB хранится вместе с распознанным текстом; Groq получает только выбранную текстовую главу.

EPUB может содержать только картинки, хотя его расширение выглядит как электронная книга. Встроенный OCR читает растровые изображения из HTML/SVG-ссылок в порядке spine, заданном книгой. Сетевые ссылки и исполняемые HTML/SVG не загружаются. При распаковке ограничены суммарный объём, число файлов и размер отдельного изображения; текст метаданных не подменяет содержание страницы. Для обычного текстового EPUB OCR не запускается без необходимости.

Удаление книги доступно учителю-владельцу прямо на карточке в библиотеке и в окне чтения. Подтверждение перечисляет удаляемые главы, тесты и результаты. Демонстрационная книга создаётся только при первом заполнении новой базы.

Для AI-тестов создаётся черновик, затем отдельным запросом проверяются однозначность вариантов, вычисления и ссылки на материал. Оба запроса используют общий таймаут 55 секунд и учитываются в бюджете Groq. Лимиты токенов провайдера могут временно ограничивать частые запросы.
